# Campus Event Pulse — Project Proposal

**Campus Event Pulse** is a campus events calendar that centralizes events from student organizations and departments into a single feed and calendar view. Students can follow organizations/categories, save events, and receive automated reminders. Organizers can submit events, and admins moderate submissions to prevent spam.

---

## Problem Statement
Campus event information is fragmented across flyers, social media, email newsletters, and scattered websites. Students miss opportunities because no single reliable, up-to-date source exists. Campus Event Pulse provides one trusted hub with fast updates and reminders.


## Major Features 

### 1. Events Feed + Calendar View
* List view (cards) and a basic calendar view 
* Filters by date range, category, organization, and location
* Search by event title or description

### 2. Organizer Event Submission 
* Manual event submission form for organizers
* CSV bulk upload support
* Validation with row-level error handling

### 3. Admin Moderation Queue
* Events are created in a `PENDING` state
* Admin moderation controls to approve or reject submissions with a reason
* Only `APPROVED` events display on the public feed

### 4. Student RSVP + Reminder Emails
* Students click "Interested" to bookmark an event
* Automated reminder emails triggered at **24 hours before** and **1 hour before**
* Preference settings to opt out of reminders

## Target Users & Value Proposition

* **Students:** One central hub to discover events, create a personalized "Interested" list, and receive timely email reminders.
* **Organizers:** A simple event posting workflow with bulk CSV uploads for recurring schedules and weekly updates.
* **Admins:** Moderation controls to ensure all published content is clean, verified, and spam-free.

## Technical Architecture 
* **Next.js :** Used as the core full-stack web framework. It handles both the frontend user interface and the backend API routes for handling requests.  
* **PostgreSQL :** Used as the relational database to store users, event submissions, organizations, RSVPs, and notification schedules.  
* **Prisma ORM:** Used to define the database schema, handle data migrations, and run database queries safely in code. 
 Email Service Provider: Used to automatically send transactional emails
